Product Requirements Document (PRD): Project PanopticonVersion: 1.2 (Execution-Ready / Sovereign Native)Concept: A lightweight, high-performance, public-domain OSINT geospatial aggregator and sensor fusion engine.Core Objective: Provide an interactive 3D globe visualizing near-real-time geopolitical events, filtered air traffic, and strategic data, orchestrated by an autonomous spatial AI assistant.1. System ArchitectureDesigned for extreme low-latency and high-throughput rendering, running completely locally/privately. Crucially, this system bypasses containerization (No Docker) in favor of a bare-metal, native process execution model to minimize I/O overhead and maximize visibility via multi-terminal stdout streams.Orchestration Layer: PowerShell native scripts (setup-env.ps1 and launch-panopticon.ps1) handling Python venv isolation, binary execution, and multi-terminal monitoring.Ingestion Edge Layer (Python): High-concurrency asyncio microservices handling WebSocket connections, ADS-B polling, and CDP (Chrome DevTools Protocol) headless browser workers for authenticated web scraping.Event Bus (NATS): A single-binary, ultra-lightweight message broker running natively. Replaces Kafka/Redpanda to ensure zero-friction bare-metal deployment while handling high-frequency telemetry routing.Core Database (SurrealDB): Multi-model database running via native CLI, handling graph relations (e.g., [Aircraft] -> BELONGS_TO -> [Entity]), vector embeddings (news/events), and geospatial querying. Data persists to a local .panopticon/data directory using the surrealkv: backend.Frontend Engine (React + CesiumJS + Vite): 3D volumetric rendering via WebGL. CesiumJS handles all geodetic math, camera controls, time-dynamic data streams, and high-performance entity instancing.AI Orchestrator (OpenRouter API + Tavily): Leverages top-tier cloud LLMs (e.g., Llama-3/Claude-3.5) for complex reasoning, dynamic context injection, and strict JSON tool-calling.2. High-Performance Filtering LogicTo maintain 60fps and prevent memory bloat, raw data is heavily filtered before database insertion and client delivery.A. Viewport-Based Spatial FilteringMechanism: The frontend continually transmits its current camera bounding box and altitude to the backend over WebSocket.Action: The backend dynamically adjusts the radius of the data firehose. If the user is zoomed in on the Black Sea, the ingestion layer only writes and streams telemetry for that specific geodetic polygon.B. Dynamic ICAO Hex Edge-FilteringMechanism: All raw ADS-B telemetry is intercepted at the edge. Standard commercial flights are immediately dropped from memory (analogous to an LDO voltage regulator filtering noise).Action: Telemetry is matched against a dynamically evolving database of military, government, and high-interest private ICAO hex codes.Three-Pronged Ingestion: 1. Static Sync: Automated pulling of known public OSINT GitHub repositories (e.g., sdr-enthusiasts/plane-alert-db).2. Manual Override: User CSV uploads for custom hex target lists.3. Agentic Discovery: The AI Orchestrator uses the Tavily API to hunt for newly identified hex codes in news/forums and injects them directly into the edge filter in real-time.3. Operational User Interface (React + Resium)Inspired by tactical systems (Project Maven/Palantir), the UI must provide granular control over the data environment.Temporal Scrubbing (Time Slider): A unified timeline control at the bottom of the UI powered by Cesium's native clock. Modifying the slider queries SurrealDB to update the viewer, allowing the user to "rewind" the globe.Layer Toggles: Quick-action buttons to instantly isolate specific telemetry (e.g., "Show only NATO ISR," "Hide GDELT News," "Overlay Sentinel-2 Terrain").Entity Cards: Clicking an aircraft or event node opens a sidebar panel displaying extracted metadata, linked X (Twitter) reports, and the AI's contextual summary of the entity.5. AI Agent Architecture & Dynamic Context InjectionThe AI Assistant relies heavily on Dynamic State Injection. The frontend continuously injects the current UI state into the LLM's system prompt before every request.Example Injected Prompt Block:[SYSTEM]
You are a spatial OSINT analyst assistant. Return actionable JSON.
[CURRENT_UI_STATE]
- Viewport: BoundingBox(Lat: 42.0 to 47.0, Lon: 28.0 to 35.0) [Black Sea Region]
- Timeline State: 2026-05-14T10:00:00Z (Historical View: -24 Hours)
- Active Layers: [ADS-B_Military, X_Scraper_Alerts]
[USER_QUERY]
"Where did that drone just come from?"
Execution: The OpenRouter LLM parses the context, queries SurrealDB via tool calling, and returns a JSON payload ({"action": "camera.trackEntity", "entity_id": "UAV_HEX_123"}) to physically pan the user's camera to the origin point.6.
